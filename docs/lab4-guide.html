2. L-architecture mn A l Z

Had schéma kayban fih chno ghadi ykoun f l-akhir. Les flèches grises homa REST (kaynin déjà). Les flèches mlwnin homa l-khedma dyal had l-lab.

F l-machine dyalkom ghadi ykounou khddamin: les 6 services l9dam + Analytics (jdid) + RabbitMQ + Kafka (b Docker).

3. Chno kaywe9e3 mli client kaychri (l-histoire kamla)

  1. Le client kaydir checkout f l-frontend. Le frontend kaysift POST /api/orders l Orders (REST, bhal daba).
  2. Orders kayjib les prix mn Catalog (REST, ma tbedel walo), o kay3iyet l Inventory b gRPC bach yréserver l-stock. Kaytsenna la réponse (synchrone) hit bla stock ma kaynach commande.
  3. Orders kaykhzen la commande b status PENDING_PAYMENT o kaypublier event OrderCreated f Kafka.
  4. Le client kaykhelles: POST /api/payments. Payments kaysajjel l-paiement o kaydir l-order PAID (REST, bhal daba).
  5. Payments kaypublier message ShipmentRequested f RabbitMQ (queue shipping_requests) o kaypublier PaymentCompleted f Kafka. Kayrja3 la réponse l client direct, bla ma ytsenna Shipping.
  6. Shipping (consumer) kayqra l-message mn la queue, kaycréer shipment, o 3ad kaysift ACK. Ila Shipping kan tayeh, l-message kayb9a f la queue tal ma ynod.
  7. Shipping kaypublier ShipmentCreated f Kafka.
  8. Analytics kayqra ga3 les events mn Kafka o kayhseb statistiques (ch7al mn commande, chiffre d'affaires…). Ila tlanca jdid, kayqra hta les events l9dam.

5. gRPC: Orders ⇄ Inventory

Tachbih: REST bhal ila kteb lik chi wahed bra twila b l-lougha l-3adiya (JSON). gRPC bhal coup de fil b code mtfa9in 3lih mn 9bel: sghir, sri3, o kolchi 3arf chno ghadi ygoul l-akhor. L-contrat dyal had l-code howa l-fichier .proto.

3lach gRPC hna?

  • Orders khasso la réponse daba (wach kayn stock?), donc khassna tawasol synchrone. RabbitMQ/Kafka ma ynasbouch hit homa asynchrones.
  • gRPC kaysift data b Protobuf (binaire, sghir bzaf 3la JSON) o 3la HTTP/2 (connexion wehda l bzaf dyal les appels).
  • Contrat strict o typé: ila chi wahed bdel champ, l-code ma ykhdemch, donc ma kaynch erreurs khfiyin.

L-contrat: proto/inventory.proto (Youssef o Taha)

syntax = "proto3";
package inventory;

service InventoryService {
  rpc CheckAvailability (AvailabilityRequest) returns (AvailabilityResponse);
  rpc ReserveStock      (StockRequest)        returns (StockResponse);
  rpc ReleaseStock      (StockRequest)        returns (StockResponse);
}

message AvailabilityRequest  { string productId = 1; int32 quantity = 2; }
message AvailabilityResponse { bool available = 1; int32 availableQuantity = 2; }
message StockItem            { string productId = 1; int32 quantity = 2; }
message StockRequest         { repeated StockItem items = 1; }
message StockResponse        { bool success = 1; }

L-code Python dyal gRPC (inventory_pb2.py) déjà commité. Ila tbedel l-.proto:

python proto/generate.py

Youssef · serveur

Inventory kaywelli fih serveur gRPC f port 50051
  • Ktbe grpc_server.py li kay-implémenter les 3 méthodes.
  • 3awed khdem b nfs la logique dyal REST (/check, /reserve, /release): dir fonctions mchtarkin, ma tktbech la logique jouj marrat.
  • Lanci serveur gRPC f thread m3a FastAPI (f lifespan), bach REST o gRPC ykhdmou b jouj.
  • Erreurs: stock ma kafich → FAILED_PRECONDITION, produit ma kaynch → NOT_FOUND.

Taha · client

Orders kay3iyet l Inventory b gRPC blast REST
  • Ktbe inventory_client.py (channel gRPC wahed kaytkhla9 mra wehda o kay3awed ytkhdem).
  • Bdel _reserve_inventory o _release_inventory f service.py bach ykhdmou b gRPC.
  • Traduire les erreurs: FAILED_PRECONDITION→409, NOT_FOUND→404, UNAVAILABLE→503, DEADLINE_EXCEEDED→504. Dir timeout (deadline) 2s.
  • Benchmark: 1000 appels REST vs 1000 appels gRPC, 9iyes l-wa9t. Hada howa l-dalil dyal "high-performance".

Kifach n3erfou bli sala

  • Commande mn l-frontend kat-créa o l-stock kaynqass (via gRPC).
  • Ila l-stock ma kafich → 409 b message wadeh.
  • Ila Inventory tayeh → 503 machi crash.
  • Tableau dyal benchmark (latence moyenne REST vs gRPC) f l-rapport.
  • Les tests dyal Orders kaydouzou.

6. RabbitMQ: Payments → Shipping

Tachbih: bhal la poste. Payments kay7et lettre f boîte aux lettres (la queue) o kaymchi f halo. Shipping kayji yakhod les lettres mli ykoun wajed. Ila Shipping kan ghayeb, les lettres kayb9aw f la boîte, ma kaydi3ouch. O mli kay9ra lettre o ysali l-khedma, kaygoul "safi" (ACK) bach tthiyed.

3lach RabbitMQ hna?

  • Le client ma khasshch ytsenna l-preparation dyal shipment → asynchrone.
  • Ila Shipping tah, l-message kayb9a f la queue (durable + persistent) → ma kaydi3 walo.
  • ACK manuel: ila Shipping tah 9bel ma ysali, RabbitMQ kay3awed ysift l-message.
  • 3lach machi Kafka? Hna 3ndna "khedma" li khass consumer wahed ydirha mra wehda o tsala. RabbitMQ msaweb l had l-cas (task queue). Kafka mzyan l l-historique o replay.

L-contrat: message ShipmentRequested

// queue: shipping_requests  (durable=true, exclusive=false, auto_delete=false)
// exchange: ""  (default)   routing key: shipping_requests   delivery_mode: 2 (persistent)
{
  "messageId": "a3f1c2e0-...",        // uuid, unique l kol message
  "type": "ShipmentRequested",
  "orderId": "order-1a2b3c4d",
  "paymentId": "payment-9f8e7d6c",
  "address": { "name": "Imane", "address": "12 Rue X", "city": "Rabat" },
  "occurredAt": "2026-11-24T10:15:00Z"
}

L-adresse kayna déjà f la commande (customer.name / address / city), o Payments déjà kayjib la commande mn Orders. Donc Payments 3ndo kolchi bach ybni l-message.

Douae · producer

Payments kaypublier mor ma l-order ywelli PAID
  • Ktbe messaging.py: connexion wehda l RabbitMQ (pika), déclarer la queue, fonction publish_shipment_requested(...).
  • 3iyet 3liha f create_payment mor l-PATCH PAID yenjah.
  • Message persistent + publisher confirms (confirm_delivery()).
  • Ila RabbitMQ tayeh: l-paiement ma ytla7ch, ghir log warning (o ymken 3awed l-envoi mn ba3d).

Imane · consumer

Shipping kayqra mn la queue o kaycréer shipment
  • Ktbe consumer.py: thread kaybda m3a FastAPI (lifespan), auto_ack=False, prefetch_count=1.
  • Handler: parse JSON → valider → créer shipment → 3ad basic_ack. Message khayeb (JSON ghalat) → basic_nack(requeue=False).
  • Idempotence: ila shipment l dak orderId déjà kayn → ACK bla ma tcréer wahed jdid.
  • Rend POST /api/shipments idempotent hta howa (ila déjà kayn → rje3 l-shipment li kayn b 200), hit le frontend ba9i kay3iyet 3lih mor l-paiement o ma 3ndnach l-7e9 nbedlou les pages.

Les tests (mn l-handout H3, b screenshots dyal localhost:15672)

  • Normal: khelles → shipment kaytcréa → la queue kat-rje3 Ready 0 / Unacked 0.
  • Shipping tayeh: 7bes Shipping, khelles → Ready 1. 3awed lanci Shipping → shipment kaytcréa bohdo.
  • Crash 9bel ACK: zid time.sleep(30) 9bel l-ACK, khelles → Unacked 1, 9tel l-process → Ready 1, lanci → kaytconsomma o ACK.
  • Ma kaytcréach shipment jouj marrat l nfs l-order.

7. Kafka: events → Analytics

Tachbih: Kafka bhal cahier dyal l-historique. Kol service kayktbe fih chno w9e3 ("commande tcréat", "paiement daz"…) f star jdid. L-ktaba ma kattmse7ch mor l-9raya. Kol wahed li bgha y9ra 3ndo marque-page dyalo (offset), o y9der yrje3 l l-bdya o y3awed y9ra kolchi (replay).

3lach Kafka hna o machi RabbitMQ?

  • F RabbitMQ, mor l-ACK l-message kaytmse7. Analytics ila kan tayeh wla tzad mn ba3d, ma ghadi yl9a walo.
  • Kafka kaykhzen les events b retention (ex. 7 iyam wla dima), o kol consumer group 3ndo offset dyalo → y9der ybda mn earliest o y3awed (replay).
  • Bzaf dyal services y9raw nfs les events bla ma y-affectiw ba3dhom (kol wahed consumer group).

L-contrat: event schema (nfs l-forma l ga3 les events)

// topic: ecommerce-events     key: orderId  (bach les events dyal nfs commande yb9aw b tartib)
{
  "eventId": "7c9e6679-...",          // uuid unique (Analytics kaystkhdmo bach ma y7sebch jouj marrat)
  "eventType": "OrderCreated",        // OrderCreated | PaymentCompleted | ShipmentCreated | ShipmentStatusChanged
  "source": "orders",                 // orders | payments | shipping
  "occurredAt": "2026-11-24T10:14:02Z",
  "orderId": "order-1a2b3c4d",
  "data": { "total": 349.0, "itemsCount": 3 }   // kaytbedel 3la 7sab eventType
}

Salma · producers

Orders, Payments o Shipping kaypubliyiw events
  • Ktbe events.py sghir (producer confluent-kafka + publish_event(type, order_id, data)), o copier-h f les 3 services.
  • Zid 1 ligne f kol blasa: OrderCreated (Orders), PaymentCompleted (Payments), ShipmentCreated + ShipmentStatusChanged (Shipping).
  • Ila Kafka tayeh: la requête ma ttla7ch, ghir log warning.
  • Créer le topic b retention (ex. 7 iyam) o 3 partitions.

Amal · Analytics

Service jdid services/analytics f port 8087
  • FastAPI + SQLite dyalo (database-per-service), consumer f thread, group.id=analytics-service, auto.offset.reset=earliest.
  • Khzen kol event f table events (eventId UNIQUE → idempotent).
  • Endpoints: GET /api/analytics/summary (nombre commandes, CA, paiements, shipments), GET /api/analytics/events.
  • POST /api/analytics/replay: msse7 les stats o rje3 l-offset l l-bdya → kay3awed y9ra kolchi.

Kifach n3erfou bli sala

  • Dir 3 commandes w Analytics tafi. Mn ba3d lanci Analytics → kayl9a les 3 (hada howa l-dalil dyal retention).
  • Replay kay3awed y7seb nfs l-arqam (ma kaytzadouch jouj marrat).
  • Consumer group akhor (ex. kafka-console-consumer) y9der y9ra nfs les events bla ma y-affecti Analytics.

12. Glossaire sghir

Synchrone
Kaysift o kaytsenna la réponse 9bel ma ykemmel.
Asynchrone
Kaysift o kaykemmel khedmto, la réponse (ila kayna) katji mn ba3d.
Protobuf
Format binaire dyal gRPC, sghir o sri3 3la JSON.
Producer / Consumer
Li kaysift l-message / li kayqrah.
Queue
Sef dyal messages kaytsennaw (RabbitMQ).
ACK
Consumer kaygoul "salit" → RabbitMQ kaymse7 l-message.
Durable / persistent
La queue o les messages kayb9aw hta ila RabbitMQ t3awed.
Idempotent
Ila 3awdti nfs l-message jouj marrat, n-natija hiya hiya (ma kaytcréach shipment jouj).
Topic
"Cahier" f Kafka fin kaytkhzno events dyal nfs l-mawdou3.
Offset
Numéro dyal l-event f l-topic, bhal marque-page.
Consumer group
Smiya dyal l-lecteur. Kol group 3ndo offset dyalo.
Retention
Ch7al mn wa9t kayb9aw les events f Kafka.
Replay
Rje3 l l-bdya o 3awed 9ra les events l9dam.
